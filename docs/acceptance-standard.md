# AdsMind 统一验收标准

本文档是 AdsMind 功能完成状态和验收要求的唯一正式来源。所有功能、分支和开发 Session 使用同一套等级、证据和缺陷标准。

## 1. 状态等级

| 等级 | 定义 | 允许使用的描述 |
| --- | --- | --- |
| L0 | 需求、边界和方案已明确，尚未形成可验证实现 | 方案完成 |
| L1 | 代码已编写，但验证不完整或尚未集成 | 开发中 |
| L2 | 分支内迁移、自动化测试、静态检查和构建通过 | 代码验证通过 |
| L3 | 已合入或基于当前统一集成基线，真实本地接口、数据库和浏览器流程通过 | 开发完成 |
| L4 | 在沙箱或测试环境中使用真实外部依赖完成端到端验收 | 验收完成 |
| L5 | 已部署生产，并完成生产环境的授权角色和关键流程验证 | 上线完成 |

等级不得跨越证据提升。生产验证不会自动补齐 L2–L4 中缺失的验证。

## 2. L3 开发完成的硬性门槛

以下项目必须全部满足：

1. 本次范围、排除项、外部依赖和已知限制明确。
2. 变更基于当前统一集成基线，不存在未解决的合并冲突。
3. 真实后端、前端和隔离测试数据库可启动。
4. 实际 HTTP 接口验证通过，并核对数据库落库和回读结果。
5. 使用实际角色完成约定的浏览器点击流程。
6. 租户、应用和角色隔离符合服务端权限规则。
7. 数据库迁移升级、回滚和再次升级通过，迁移头符合仓库约定。
8. 与变更相关的后端测试、前端测试、静态检查和构建通过。
9. P0 和 P1 缺陷均为零；P2、P3 缺陷已记录并评估影响。
10. 验收记录包含 Commit SHA、环境、步骤、实际结果、测试数量、跳过项和未完成项。

任一硬性门槛缺失时，最高为 L2。

## 3. 接口验收标准

接口验收必须调用正在运行的真实本地后端和隔离测试数据库。服务层单测、Mock 客户端或直接调用函数不能替代实际 HTTP 验收。

### 3.1 必测场景

- 正常请求和关键业务状态变化。
- 参数缺失、格式错误和业务校验失败。
- 未登录、登录失效和无权限。
- 跨租户访问。
- 同租户跨应用访问。
- 重复请求、幂等或重复提交。
- 依赖失败、超时及其他适用的错误响应。

### 3.2 结果核对

HTTP 200 本身不代表通过。必须同时核对：

- 状态码和响应结构符合接口契约。
- 返回数据属于正确的租户、应用和角色范围。
- 数据库记录、状态转换和关联关系正确。
- 刷新或重新请求后可以正确回读。
- 需要审计的操作生成正确审计记录。
- 失败请求没有产生不应出现的部分写入。
- 错误响应不泄露其他租户或应用的数据是否存在。

验收记录需保留可复现的请求步骤、关键响应和数据库回读结果。密钥、令牌和个人数据不得写入仓库。

## 4. 浏览器点击验收标准

浏览器验收必须连接本次启动的真实前后端，并使用与功能相符的实际角色。静态页面、组件快照和只读截图不能替代完整操作。

### 4.1 必测流程

根据功能适用范围覆盖：

- 页面入口、菜单可见性和直接访问路由。
- 查询、筛选、排序、分页和详情查看。
- 创建、编辑、提交、取消和删除。
- 刷新、返回、重新进入后的状态保持和数据回读。
- 空数据、加载中、无权限、表单校验和后端失败状态。
- 防重复点击、重复提交和操作中的按钮状态。

### 4.2 通过条件

- 约定验收路径可以完整走通。
- 页面无白屏、死按钮、错误跳转和明显状态错乱。
- 网络请求无意外 404/500，失败场景有明确反馈。
- 验收路径中无未处理的浏览器控制台错误。
- 页面显示与接口响应及数据库状态一致。
- 刷新后不依赖仅存在于前端内存中的临时状态。
- 前端权限展示和服务端权限拒绝一致。

“网页点击无 Bug”指约定验收路径内无阻塞缺陷、无 P0/P1、无未处理控制台错误。它不表示不存在任何潜在缺陷。发现的 P2/P3 必须写入验收记录。

## 5. 租户、应用和角色隔离

### 5.1 租户隔离

- 不同租户拥有独立业务数据范围。
- 列表、详情、搜索、统计、导出和写入均受租户约束。
- 跨租户资源不能通过猜测 ID、修改参数或直接调用接口访问。

### 5.2 应用隔离

- 同一租户内，不同应用的数据和配置按定义隔离。
- 共享数据必须经过明确的数据模型和授权规则，不能依赖前端约定。
- 应用标识由服务端校验，不能只信任客户端传值。

### 5.3 角色权限

- 至少验证允许角色、只读角色和无权限角色。
- 菜单或按钮隐藏不能替代服务端鉴权。
- 对不存在和无权访问资源的响应必须符合安全约定。
- 用户级权限覆盖存在时，必须纳入实际用户验收。

## 6. 数据库和迁移验收

涉及表、字段、索引、约束或数据迁移时，必须验证：

- 全新隔离数据库可以升级到最新版本。
- 已有基线数据库可以升级。
- 回滚到上一版本成功。
- 回滚后再次升级成功。
- 数据约束、唯一性、外键和索引符合设计。
- 历史数据兼容，失败时不会静默丢失或伪造数据。
- 迁移头数量符合仓库约定，禁止通过 stamp、改写历史迁移或降级版本掩盖漂移。

## 7. 自动化检查

验收记录必须写明实际执行的检查及结果：

- 后端测试数量、通过数、失败数和跳过数。
- 前端测试数量、通过数、失败数和跳过数。
- 类型检查、静态检查和生产构建结果。
- 与本次功能直接相关的专项测试。
- 未执行的检查及原因。

只写“测试通过”不构成完整证据。不得把跳过项计为通过。

## 8. 缺陷等级

| 等级 | 定义 | 对验收的影响 |
| --- | --- | --- |
| P0 | 数据泄露、严重安全问题、不可恢复的数据损坏或系统整体不可用 | 阻止 L3–L5 |
| P1 | 核心流程不可用、权限绕过、严重数据错误或无可接受替代路径 | 阻止 L3–L5 |
| P2 | 非核心流程异常、有明确替代路径但影响正常使用 | 必须记录并确认处理计划 |
| P3 | 轻微交互、文案、视觉或低影响问题 | 必须记录，可排期处理 |

缺陷等级按实际影响判断，不能通过降低等级规避硬性门槛。

## 9. 验收证据

每项功能使用 [`acceptance/TEMPLATE.md`](acceptance/TEMPLATE.md) 建立独立记录。有效证据包括：

- 精确的分支和 Commit SHA。
- 验收日期、环境和角色。
- 可复现的接口和浏览器步骤。
- 关键响应、数据库回读和审计结果。
- 自动化检查的实际数量和结果。
- 缺陷、跳过项、外部依赖和下一等级阻塞项。

截图可辅助说明页面状态，但不能单独证明接口、落库、隔离或完整流程通过。

以下内容不能单独证明“开发完成”：

- 已提交代码或已有 Commit。
- 单元测试、构建或静态检查通过。
- Mock、fixture、dry-run 或静态演示。
- 页面能打开或某个按钮能点击。
- HTTP 200，但未检查响应和落库。
- 本地存储成功，但真实外部依赖未验证。
- 平台预检通过，但没有实际端到端结果。
- 功能分支完成，但尚未同步统一集成基线。

## 10. L4 和 L5 的额外要求

### L4：验收完成

- 在指定沙箱或测试环境部署当前候选版本。
- 使用真实外部服务、凭据和回调完成授权范围内的端到端流程。
- 验证失败恢复、重复请求、超时和状态回查。
- 记录外部平台对象、时间、结果和数据范围，但不提交秘密信息。

### L5：上线完成

- 明确生产版本、Commit SHA、部署时间和变更范围。
- 完成健康检查、关键接口、实际角色、关键页面和权限验证。
- 核对数据库迁移和生产数据兼容性。
- 明确监控、回滚方式和遗留问题。
- 只有公开生产环境验证成功后才可使用“已上线”。

## 11. 验收结论格式

每次验收必须给出一个明确结论：

```text
当前等级：L2
允许描述：代码验证通过
未达到 L3 的原因：尚未完成真实 HTTP 和浏览器流程验收
P0/P1：0/0
P2/P3：1/2
下一步：修复 P2，并补齐实际角色的浏览器验收
```

如果证据不足，应降低等级并写明缺失内容，不能使用“基本完成”“大致可用”等无法验证的表述。
